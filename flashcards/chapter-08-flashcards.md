## Chapter 8: Agentic Systems and Tool Use — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | LangChain AgentExecutor default max_iterations? | 15. Exam tip: prevents infinite tool-calling loops. Increase only when a task genuinely needs more steps — otherwise treat looping as a design smell, not a limit to raise. |
| 2 | What is the ReAct pattern? | Reasoning + Acting loop: the LLM alternates between generating a thought, choosing a tool action, observing the result, and repeating until it decides to finish. It's the foundation of most agent frameworks. |
| 3 | LangChain vs LlamaIndex — core focus? | LangChain: general-purpose orchestration, agents, and chains across many tool types. LlamaIndex: data ingestion/indexing and retrieval-first RAG pipelines. Exam tip: pick LlamaIndex for 'many data sources', LangChain for 'multi-step agent workflow'. |
| 4 | Required fields in an OpenAI-style tool/function schema? | name, description, parameters (as JSON Schema). The description drives whether and when the model selects the tool — vague descriptions cause wrong tool selection. |
| 5 | When should you use a simple chain instead of an agent? | When the task has a fixed, known sequence of steps with no need for the model to decide what happens next. Agents add latency, cost, and failure surface (loops, wrong tool calls) — only justified when the next step genuinely depends on prior output. |
| 6 | parallel_tool_calls default behavior (OpenAI-style tool calling APIs)? | Defaults to allowing the model to call multiple tools in one turn. Exam tip: disable parallel calling when tool calls must execute strictly sequentially (e.g., one depends on a prior call's side effect). |
| 7 | Short-term vs long-term vs episodic memory in agents? | Short-term: current conversation/context window (ephemeral). Long-term/semantic: persistent, generalized facts/preferences stored externally (vector DB/KV store), surviving across sessions. Episodic: record of specific past interactions/experiences the agent can recall and reason over. |
| 8 | Multi-agent collaboration — when is it justified? | When subtasks require genuinely different roles/expertise/tools (e.g., researcher + coder + reviewer) and coordination overhead is worth it. Exam trap: using multi-agent for a task one well-prompted single agent could handle adds cost/latency/failure points without benefit. |
| 9 | Core guardrail techniques for agentic systems? | Step/iteration limits, tool allow-lists (restrict callable tools), output validation/schema enforcement, human-in-the-loop approval for high-risk actions, and sandboxed tool execution. Exam tip: 'unrestricted tool access' is almost always the wrong answer. |
| 10 | Custom orchestration vs a framework (LangChain/LlamaIndex) — when to build custom? | Build custom when you need minimal dependencies, tight latency/cost control, or the framework's abstractions don't fit a simple flow. Choose a framework when you need built-in memory, tracing, and prebuilt integrations delivered quickly. |
| 11 | tool_choice parameter — common values in tool-calling APIs? | 'auto' (model decides whether/which tool to call), 'none' (no tool call allowed), 'required' (must call a tool), or a forced specific tool name. Exam tip: use 'required' or a forced name when structured output via a tool call must be guaranteed. |
| 12 | Exam trap: agent vs chain judgment call — quick rule? | If the requirement says 'always follow these exact steps' → simple chain. If it says 'decide which tool/action based on the situation' → agent. Choosing an agent for a fixed, non-branching workflow is the most commonly missed wrong answer. |
